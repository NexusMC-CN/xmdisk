# 01 · 产品定义与边界

## 定位

- Go 开发的单二进制自建存储服务，面向业务平台提供标准存储接口；不做面向终端用户的控制台。
- 主从异步复制（异地备份），手动运维切换，不做多主与自动切换。
- 业务平台按存储容量计费（本服务提供用量数据），流量计费归网关。
- 集群管理控制台是**后续独立项目**（自带 WebUI，经 admin API 批量编排）；存储本体保持单节点精简。控制台能力全部以"单节点 admin API + 文档化 runbook"为底——只做编排，不引入节点间管理通道或隐藏路径（99-D015）。

## 协议优先级

| 优先级 | 协议 | 定位 | v1 范围 |
|---|---|---|---|
| 1 | S3 | 业务平台主接口 | PUT/GET/DELETE/HEAD、ListObjectsV2、multipart、条件请求、presigned URL；path-style；SigV4。兼容目标：主流 SDK、aws-cli、rclone |
| 2 | SFTP | 人工/定时备份场景 | open/read/write/rename/mkdir/rmdir/listdir/stat；固定 uid/gid。不做：symlink、hardlink、xattr、锁。目标客户端：WinSCP、FileZilla、sshfs、rsync、paramiko |
| 3 | WebDAV | 顺带提供 | x/net/webdav 适配，best effort；排期紧张时第一个砍 |

三协议共享同一命名空间（bucket + key 树）、同一套桶级凭据与配额。

## 设计上限

上限是性能承诺的边界，不是数据安全的边界：超出后正确性仍然成立，但延迟、快照时长、内存占用不再保证。

| 维度 | 设计目标 | 尽力而为 |
|---|---|---|
| 全局对象总数 | ≤ 1000 万 | ≤ 5000 万（届时评估 pebble 替换元数据引擎） |
| 单桶对象数 | ≤ 500 万 | — |
| 单对象大小 | 单次 PUT ≤ 5GB（对齐 S3 规范） | multipart ≤ 1TB（可配） |
| 存储池容量 | 16TB 起步 | — |

文件画像不可预知（大小混杂）。小文件海量场景的将来优化手段是"小 blob 打包进段文件"（SeaweedFS volume 思路），不改变现有地基。

## 必做清单

单二进制 + 单配置；S3/SFTP/WebDAV 三协议；主从异步复制（快照 + oplog）；完整性校验（入库哈希 + verify 抽查）；admin API（status/snapshot/gc/verify/promote/serve/sync/creds）；Prometheus 指标；协议入口 TLS；复制通道认证。

## 明确不做

多主、自动故障切换、共识协议；Web 控制台（本体不内置；独立控制台项目后续开发，见定位）；IAM/ACL/bucket policy（静态桶级凭据）；多租户与配额平台化；纠删码（单节点磁盘冗余交给文件系统/RAID）。

## 暂缓（设计留口）

versioning（元数据已留 seq/mtime）；blob 静态加密（密钥等级与凭据主密钥严格分离，见 02）；zstd 压缩；半同步复制开关；S3 事件通知；KEK 轮换命令。
