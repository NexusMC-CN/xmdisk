# 05 · 部署与配置

## 部署拓扑

- 常态：**1 主 + N 从**（多从为常态，异地备份）。从节点只与主节点的 repl 端口通信；业务流量经反向代理只到主节点。
- 未来独立控制台（自带 WebUI）经各节点 admin API 批量编排，不改变节点间通信模型。

## 数据目录布局

data_dir 单节点自包含，整个目录即备份单元：

```
/var/lib/xingmeng/
  meta.db            # SQLite：entries/buckets/creds/oplog/slaves/multipart 会话
  meta.db-wal/-shm
  node-state.json    # 运行态：role/epoch/serve/sync（promote 等运行期变更写这里）
  snapshots/         # VACUUM INTO 快照 + manifest（含截断点 seq）
  blobs/ab/cd/<sha256>
  trash/<sha256>     # 待清扫 blob，文件 mtime 即标记时间
  tmp/               # 入库暂存：写满 fsync 后原子 rename 进 blobs/
```

## 配置体系（99-D023：优先级 运行态 > env > YAML > 默认值）

- **运行态**（data_dir/node-state.json，API/WebUI 可改）：role/epoch/serve、最近同步地址、运行时 repl token——重启优先于一切初值。
- **env（XM_\*，出生初值）**：docker 形态的主配置面（MySQL root 密码模式，方便自动化全 env 起集群）；覆盖 YAML 同名项。
- **YAML**：可选文件（缺省全默认），适合放监听口与存储调优这类"改了要重启"的参数。
- **必填拒启**：`XM_KEK` 与 `XM_ADMIN_TOKEN` 缺失拒绝启动（监听 0.0.0.0 的容器形态倒逼；裸机同样适用）。

| 环境变量 | 必填 | 说明 |
|---|---|---|
| `XM_KEK` | 是 | 凭据主密钥，主从同值；丢失走批量重置（99-D009） |
| `XM_ADMIN_TOKEN` | 是 | admin 面长期凭证（换会话 token / curl 直用） |
| `XM_ROLE` | 否 | master（默认）/ slave；**仅出生初值**，promote 后以运行态为准（改 env 不会翻转已有数据的节点角色，只触发启动 WARN 软提醒） |
| `XM_REPL_TOKEN` | 否 | 复制面凭证，主从同值；**为空 = 不监听复制面**（单节点零暴露）。也可运行时经 `POST /repl/token` 设置（KEK 封装持久化，优先于 env） |
| `XM_MASTER_ADDR` | 否 | 从节点初始主地址；可后经 `POST /sync` 指定并持久化 |
| `XM_DATA_DIR` | 否 | 数据目录（默认 ./var；镜像内置 /var/lib/xmd） |
| `XM_PUBLIC_ENDPOINT` | 否 | 对外展示地址（WebUI 连接信息用，如 http://storage.example.com:9000） |
| `XM_WEBUI` | 否 | on（默认）/ off，内嵌管理页开关 |

```yaml
node:
  role: master              # master | slave，仅初值；运行期变更持久化于 node-state.json
  data_dir: /var/lib/xingmeng
listeners:
  data_http: 0.0.0.0:9000   # S3（根路径，path-style）+ WebDAV（/dav/<bucket>）
  data_ssh:  0.0.0.0:9001   # SFTP（留空 = 不启用）
  admin:     0.0.0.0:9002   # admin API + WebUI（admin token 必填；裸机仅本机可改 127.0.0.1）
  repl:      0.0.0.0:9003   # 复制面（repl token 为空时不监听）
  public:    0.0.0.0:9004   # 公共读面（99-D024：仅认桶公共标志；反代公共域名指向这里）
storage:
  blob_small_threshold: 4MB
  chunk_size: 8MB
  multipart_max_object: 1TB
  multipart_abort_after: 168h
replication:
  master_addr: ""           # 初值；运行态（API 设置）优先
  token: ""                 # repl 面共享凭证初值；为空不监听
admin_token: ""             # 建议用 XM_ADMIN_TOKEN；空 = 拒绝启动
log: { level: info }
```

- **KEK 只从环境变量读取**（`XM_KEK`），不进配置、不进库；开发期用 .env（进 .gitignore）。
- 配置与运行态分离（99-D016）：配置管理工具可随意重写配置文件，不会覆盖 promote 产生的运行态；灾难重建（清元数据）连带清 state，节点回到配置初值。

## docker 形态（拉起即用）

```bash
# 单节点（最小形态）
docker run -d -p 9000:9000 -p 9001:9001 -p 127.0.0.1:9002:9002 \
  -v xmd-data:/var/lib/xmd \
  -e XM_KEK=<长随机串> -e XM_ADMIN_TOKEN=<长随机串> \
  xmd:latest

# 从节点（加入集群；repl token 主从同值，主节点另需 -p 9003:9003）
docker run -d -e XM_KEK=<同值> -e XM_ADMIN_TOKEN=<各自> \
  -e XM_ROLE=slave -e XM_REPL_TOKEN=<同值> \
  -e XM_MASTER_ADDR=http://<主>:9003 \
  -v xmd-data2:/var/lib/xmd xmd:latest
```

- 镜像内置仅含监听口的默认 YAML（`xmd.docker.yaml`）；挂载自定义配置：`docker run ... xmd -config /your/xmd.yaml`。
- 镜像 HEALTHCHECK 带 `X-Xm-Token` 头探活 admin 面（admin 面全端点鉴权）。
- 公共读面（99-D024）：需要对外提供直链时 `-p 9004:9004`，并在 web 服务器把公共域名反代到它（无 Host 透传负担，`proxy_buffering off` 即可）；桶开关在 WebUI/`PATCH /buckets/{name}`。
- 容灾切换零重建：从节点 WebUI 点 promote（升主、接管复制面、serve=ro）→ 确认后开 rw → 其余从节点在各自 WebUI 重指同步地址（持久化，重启不回落）。旧主回归按 docs/03 runbook 处置，不做"一键降格"。

## 安全基线（99-D023）

1. **admin（:9002）与 repl（:9003）不进公网**。发布习惯：`-p 127.0.0.1:9002:9002` 而非 `-p 9002:9002`；远程管理走 SSH 隧道（`ssh -L 9002:localhost:9002`）或 nginx TLS 反代。
2. admin token / repl token / KEK 均为长期凭证：`docker inspect` 可见 env，与数据卷同属宿主机权限边界——宿主机加固是前提；轮换 admin token = 重建容器（env 初值），repl token 可 API 轮换（主从逐台）。
3. 明文 HTTP 下 token 可被抓包——传输安全靠部署层（隧道/反代 TLS），双 token 机制解决的是凭证泄露后的时效与吊销，两者互补。
4. WebUI 与 admin API 同端口同凭证，无额外暴露面；会话 token 短时效且可吊销，浏览器端不长期保存 admin token。
5. **公共读（99-D024）**：开启公共读的桶等于放弃该桶对象的访问控制——公共读端口（:9004）上任何人可用 URL 直接读取（key 可猜测=可读取）。仅分发类资产开公共；需要临时分享用 presign。公共读端口不发缓存头，缓存策略由你的反代/web 服务器自行配置；域名绑定与 URL 改写亦归反代层。

## 对外工作方式说明（供业务平台侧配置代理）

1. HTTP 数据口（:9000）可被标准 HTTP 反向代理（nginx / haproxy / 云 LB）代理，两条硬要求：
   - **透传 Host 头、不改写路径**——SigV4 签名覆盖 Host，presigned URL 同理；改了 Host = 全部签名失败，这是 S3 兼容服务接反代最常见的坑；
   - 大文件关闭请求/响应缓冲（nginx：`proxy_request_buffering off` + `proxy_buffering off`），否则反代先落盘再转发，吞吐减半还占双倍空间。
2. SFTP（:9001）是 SSH 协议，HTTP 反代无法代理：需四层转发（nginx stream / haproxy tcp 模式）或直接暴露端口。
3. admin（:9002）与 repl（:9003）不进公网代理；repl 走内网/VPN，两端同 KEK（见 02 凭据与主密钥）。
4. `/health` 返回 2xx 即存活，可作探活语义；`/status` 供人看。
