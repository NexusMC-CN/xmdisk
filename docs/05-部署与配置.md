# 05 · 部署与配置

## 部署拓扑

- 常态：**1 主 + N 从**（多从为常态，异地备份）。从节点只与主节点的 repl 端口通信；业务流量经反向代理只到主节点。
- 未来独立控制台（自带 WebUI）经各节点 admin API 批量编排，不改变节点间通信模型。

## 数据目录布局

data_dir 单节点自包含，整个目录即备份单元：

```
/var/lib/xingmeng/
  meta.db            # SQLite：entries/buckets/creds/oplog/slaves/multipart 会话
  meta.db-wal/-shm
  node-state.json    # 运行态：role/epoch/serve/sync（promote 等运行期变更写这里）
  snapshots/         # VACUUM INTO 快照 + manifest（含截断点 seq）
  blobs/ab/cd/<sha256>
  trash/<sha256>     # 待清扫 blob，文件 mtime 即标记时间
  tmp/               # 入库暂存：写满 fsync 后原子 rename 进 blobs/
```

## 配置文件（仅初值）

```yaml
node:
  role: master              # master | slave，仅初值；运行期变更持久化于 node-state.json
  data_dir: /var/lib/xingmeng
listeners:
  data_http: 0.0.0.0:9000   # S3（根路径）+ WebDAV（/dav/<bucket>）
  data_ssh:  0.0.0.0:9001   # SFTP
  admin:     127.0.0.1:9002
  repl:      0.0.0.0:9003
storage:
  blob_small_threshold: 4MB
  chunk_size: 8MB
  multipart_max_object: 1TB
  multipart_abort_after: 168h
replication:
  master_addr: ""           # slave 填
  token: ""                 # repl 面共享凭证
  snapshot_interval: 6h
  log_retention: 48h
  gc_grace: 48h
  bandwidth_limit: 0        # 0=不限；从节点拉取限速
sftp:
  host_keys: []
log: { level: info }
```

- **KEK 只从环境变量读取**（`XM_KEK`），不进配置、不进库；开发期用 .env（进 .gitignore）。
- 配置与运行态分离（99-D016）：配置管理工具可随意重写配置文件，不会覆盖 promote 产生的运行态；灾难重建（清元数据）连带清 state，节点回到配置初值。

## 对外工作方式说明（供业务平台侧配置代理）

1. HTTP 数据口（:9000）可被标准 HTTP 反向代理（nginx / haproxy / 云 LB）代理，两条硬要求：
   - **透传 Host 头、不改写路径**——SigV4 签名覆盖 Host，presigned URL 同理；改了 Host = 全部签名失败，这是 S3 兼容服务接反代最常见的坑；
   - 大文件关闭请求/响应缓冲（nginx：`proxy_request_buffering off` + `proxy_buffering off`），否则反代先落盘再转发，吞吐减半还占双倍空间。
2. SFTP（:9001）是 SSH 协议，HTTP 反代无法代理：需四层转发（nginx stream / haproxy tcp 模式）或直接暴露端口。
3. admin（:9002）与 repl（:9003）不进公网代理；repl 走内网/VPN，两端同 KEK（见 02 凭据与主密钥）。
4. `/health` 返回 2xx 即存活，可作探活语义；`/status` 供人看。
