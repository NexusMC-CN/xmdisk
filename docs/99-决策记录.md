# 99 · 决策记录（ADR）

格式：编号 · 决策 · 理由 · 被否方案。定稿后不删除；要修改时新增条目并引用旧编号。

- **D001 元数据引擎选 SQLite（WAL）而非 KV/自研** — 同事务多表一致性是配额计数、oplog 原子性、崩溃安全的根基；千万对象内性能充裕（库 GB 级、点查微秒级、WAL 多读并发、写串行即 group commit）；VACUUM INTO 快照免费；sqlite3 可肉眼排障。被否：pebble/badger（跨键一致性要自建；触发条件=5000 万对象）、bbolt（快照=全量拷贝）、MinIO 式"元数据随数据存、无全局目录"（无树语义与全局视图，SFTP rename、目录实体、复制事件都做不了）。
- **D002 数据面内容寻址（sha256）** — 复制只传缺失 blob、收包自带完整性校验、去重免费、分叉后重建便宜（blob 永远有效，只需重建元数据）。代价：磁盘不可读（已接受，后续用 admin cat 类工具补）。被否：路径明文布局（复制与 GC 实现脏、无去重）。
- **D003 oplog 全量状态 op + JSON 编码** — 幂等、按 seq 回放即正确；元数据 op 每秒几百条，压缩无意义，肉眼可读是真价值。被否：增量 diff（实现复杂且难排障）、CBOR/msgpack（省不了多少）。
- **D004 快照 + tail 解决晚加入从节点** — 快照本身就是合并态。被否：全量历史保留（空间）、按 key 日志压缩（tombstone 与保序复杂度高一个量级）。
- **D005 手动故障切换 + epoch fencing** — 此前黑盒自动化出过事；原则是机器只做校验和执行、决策永远在人。被否：自动提升（网络分区误判、分叉风险）。
- **D006 blob 两阶段 GC + 墓碑感知** — 从节点 GET 到墓碑得到明确跳过信号，消除"删除与同步赛跑"的重试风暴；清扫前重验存活，自愈不误删。被否：引用计数（崩溃/并发窗口会丢数据）。
- **D007 协议优先级 S3 > SFTP > WebDAV** — 砍任何协议都不省存储层（树语义因 SFTP 必须存在），只省适配器；WebDAV 边际成本最小但需求最弱，压力来了先砍它，永远不砍 S3。
- **D008 配额/计费用逻辑字节，计数器同事务维护** — 与 S3 计费口径一致；同事务带来零漂移、无竞态、审计免费；pending_bytes 堵 multipart 白嫖洞；物理字节仅作指标（差值=去重收益）。
- **D009 secret 可逆加密（AES-GCM + KEK 环境变量）** — SigV4 要求持明文重算 HMAC，不能单向哈希；KEK 部署级共享（从节点提升后必须能验签）；丢失走批量重置（平台提交明文或 rotate 生成新 SK）。红线：KEK 只保护可重置状态，永不保护不可重建数据。
- **D010 multipart 会话不复制** — 从节点只拉被 entry 引用的 blob，Complete 时批量补；主挂丢在途上传，客户端重试符合 S3 语义，换来会话状态完全本地化。
- **D011 tree_move 单 op** — 目录 rename 从节点本地一个事务重写前缀，防大目录移动打爆 oplog；主节点侧同写事务扫描重写，串行写保证原子。
- **D012 三监听面（数据/admin/repl）先分端口后补鉴权** — 事后拆监听比事后加中间件麻烦得多；开发期绑 127.0.0.1 即无鉴权测试形态。
- **D013 无"主转从"专用操作** — 排空后的旧主（同历史）走标准从节点接入续传，无需重建；分叉节点（含比新主超前的从）走"清元数据、保 blob"重建。两种情况都被现有路径覆盖，不存在也不需要 demote 命令。
- **D014 节点状态机三开关 role/serve/sync** — promote 是唯一改 role 的途径且自带前置校验；写入仅发生于 role=master ∧ serve=rw；serve 拆 ro/rw 两段让"先只读冒烟、再放开写入"成为标准动作。
- **D015 管理分层：本体单节点精简，批量编排归未来控制台** — 多从为常态，但节点本体只提供单节点 admin API；未来独立控制台（WebUI）经 admin API 批量编排（如灾备 runbook A4 的逐台重指），等价于文档化步骤的自动化，不引入节点间管理通道或隐藏状态。
- **D016 配置与运行态分离** — 配置文件只声明初值（role/epoch/serve/sync）；运行期变更持久化于 data_dir/node-state.json，重启时 state 优先于配置。配置管理工具重写配置不会覆盖 promote 产生的运行态；灾难重建（清元数据）连带清 state 回初值。
- **D017 错误映射三原则** — Store 层单一错误枚举；三协议各一张穷举映射（启动期完整性检查，新错误漏配即拒绝启动）；S3 错误用标准 XML、以 Code 为准；QuotaExceeded 取 507（403 会被 SDK 误判为凭证问题）。
- **D018 符号链接加固（防跳板，非 ../ 穿越）** — 架构上 key→SQLite、内容→哈希命名文件，协议层无法注入链接（SFTP symlink 操作直接拒绝）；但文件系统层植入（备份还原带出、恶意软件）是真实残余风险：blob 一切路径操作 Lstat 强制普通文件、分片目录链必须真实目录、trash 里的链接只删不复活、Put 遇链接占位铲除重写、List/清扫过滤非常规文件。源自用户在备份还原项目的真实事故。
- **D019 流式配额守卫** — 原"先落盘后事务校验"允许流式特大文件在被拒前写满磁盘（磁盘是全局资源，单桶配额保护不了别的桶）。守卫：写 blob 前预读桶计数快照计算额度（含覆盖写/重传 part 的旧空间抵扣），读超即刻中断、磁盘零残留；快照非原子（并发超额上界=各流起步额度之和），权威校验仍在提交事务内；不限桶由 MaxObjectSize/MultipartMaxSize 兜底。
- **D020 从节点本地 GC** — 从节点的孤儿 blob（主节点删除后本地副本）由从节点自己的标记-清扫回收：滞后安全性由"回放时缺失即回源拉取"兜底（主节点要么仍持有、要么已墓碑/清理——后者对应日志里随后的删除 op）。主节点 GC 的从节点 ack 门控只管主侧。
- **D021 SFTP 认证与命名空间映射** — 复用凭据表：用户名=AK、密码=SK（常数时间比较），认证成功即以凭据绑定的桶为根目录（租户隔离免实现）；公钥认证后补（需 creds 表加列）。读写走临时文件 + Close 提交（保持"先内容后元数据"），**WriteAt 即刻限流**（D019 在 SFTP 路径的延续：临时文件同样不能等提交才发现超额）；读路径 ReaderAt 每次区间读走跨 blob 拼接；Setstat 支持 mtime/chmod（rsync -a、WinSCP 依赖）。
- **D022 WebDAV 映射** — Basic 认证=凭据表 AK/SK 且须绑定挂载桶，挂载点 /dav/<bucket> 与 S3 同端口路径路由（名为 dav 的 S3 桶会被遮蔽，可接受）；锁用进程内 MemLS；PROPPATCH（死属性）暂缓；写路径同 SFTP（临时文件 + Close 提交 + WriteAt/Write 即刻限流）；配额预检在路由层（带 Content-Length 的 PUT 直接 507），无长度流式由写入限流兜底——x/net/webdav 把写错误固定映射为 405，记为已知偏离（docs/06）。
- **D023 发行面与管理面 v2：env 出生初值 + 运行态优先 + 内嵌极简 WebUI + 双 token 会话** — docker 拉起即用为目标。① 配置优先级：运行态（node-state.json，API 可改）> 环境变量（XM_*，出生初值，MySQL root 密码模式，方便自动化全 env 起集群）> YAML > 默认值；配置文件可选（缺省全默认），端口保留默认值+覆盖（不硬编：裸机形态与本机多节点测试仍需改端口）。② 必填拒启：XM_KEK 与 XM_ADMIN_TOKEN 缺失拒绝启动（容器内监听 0.0.0.0 倒逼；"空=不鉴权"仅存于包内测试直连形态）。③ repl 面新语义：repl token 为空 = 不监听复制面（修复"空 token 0.0.0.0:9003 裸奔"漏洞）；repl token 与主地址可经 admin API 设置并持久化（token 用 KEK 封装存 node-state.json——不进 meta.db，因从节点 bootstrap 会整库替换 meta.db；地址明文存 state）。集群操作全程 API/WebUI，零容器重建。④ 角色护栏为软提醒：state 优先于 env（promote 后重启不误降级）；不一致时启动日志 WARN + status 暴露 configured_role + WebUI 横幅；主降从机制上不存在（D013），改 env 无法翻转已有数据的节点角色。⑤ 双 token：admin token 可经 POST /auth/session 换短时会话 token（TTL 1-24h 自选、内存态、重启清空、可吊销/登出）；除签发端点外全部接口双轨接受（X-Xm-Token / X-Xm-Session），curl/脚本与未来控制台零迁移；比较一律常数时间。⑥ WebUI：go:embed 单页挂 admin 端口（同源免 CORS/cookie/CSRF），范围=现有 admin API 表单化（状态/桶/凭据/serve/sync/promote/snapshot/gc/verify/集群配置）+ 连接信息面板（生成 mc/rclone 可复制配置片段替代文件管理器）；不做对象浏览器与多节点编排（后者仍归 D015 独立控制台）。同步地址持久化进 state（重启自动恢复到最近主节点，容灾重指后重启不再回落旧地址）。
